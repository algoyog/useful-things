Part 1 · First Principles

Why AI-DLC Exists — From First Principles

Strip away all buzzwords. Every folder, hook, stage, and ritual in AI-DLC exists to solve four fundamental physics problems of building software with AI.

First Principle #1 Speed vs Structure

LLMs are probabilistic, not deterministic

The Root Problem: If you ask an LLM to remember what stage is next, what you approved 20 messages ago, or whether tests passed, it will eventually drift — especially after context compaction.
AI-DLC's Solution: Split the job cleanly. Tools own determinism (state files, stage routing, receipts, audit logs, sensors). LLMs own knowledge (design, coding, explaining trade-offs).
First Principle #2 Quick-Cement Problem

Unchecked AI code hardens into "quick-cement"

The Root Problem: AI writes thousands of lines in minutes. If an early requirement or architecture assumption is wrong, AI rapidly pours massive code on top of the mistake.
AI-DLC's Solution: Minimal, sharp human approval gates as a "loss function" (plus adversarial reviewers & Walking Skeletons) catch mistakes while changes are still cheap.
First Principle #3 Google Maps Model

Reverse the conversation direction

The Root Problem: In "AI-Assisted" coding, humans manually break down tasks and micro-prompt the AI — bolting an engine onto a horse-drawn chariot.
AI-DLC's Solution: You set the destination (Intent). AI proposes the route, asks clarifying questions, presents trade-offs, and runs rapid Bolts — while you hold the steering wheel.
First Principle #4 Compounding Context

Chat history evaporates; repo artifacts compound

The Root Problem: When a chat session ends or compacts, every design decision and "why" vanishes. The next session starts blind.
AI-DLC's Solution: Persist every Intent, Story, DDD model, ADR, state checkbox, and audit event inside aidlc/ as Context Memory — so every stage makes the next smarter.

The 4 Golden Tenets (Strict Priority Order — #1 Wins Any Conflict)

From AGENTS.md
1. Human drives the engine
You keep the wheel. Plain-English status, undo paths, asks once, never refuses an explicit request.
2. Tools for determinism
Scripts & hooks handle routing, state, receipts, and guards identically every time.
3. LLM for knowledge
Agents bring coding, architecture, security & testing expertise and explain options simply.
4. Human for judgement
You decide what to build, trade-offs, and gate approvals.

    Part 5 · Techniques & Practices

    Every Execution Technique, Collaboration Ritual & Practice

    The concrete engineering practices that make AI-DLC reliable on real codebases.

    4 Stage Execution Modes (How Agents Collaborate)

    1. Inline
    Direct in Chat
    Default mode. Conductor wears the lead agent's hat in the main chat for fast real-time Q&A.
    2. Subagent (Hub)
    Isolated Focus / Spokes
    Dispatches a separate agent context (e.g., Code Generation, or Practices Discovery with 3 blind spokes).
    3. Pipeline
    Ordered Chain
    Agents run in strict order, each seeing all upstream output with receipts (e.g., Reverse Engineering).
    4. Mob Mesh
    Mutually Blind Rounds
    Lead drafts, blind collaborators critique/contribute in parallel, lead integrates (e.g., User Stories).

    5-Layer Additive Rules Chain (memory/)

    Strictly additive: broader rules are never silently deleted — each layer adds specificity.
    1. org.md→ 2. team.md→ 3. project.md→ 4. phase→ 5. stage

    Survives context compaction and multi-session resumes cleanly.
    [ ] Pending
    [-] In Progress
    [?] Waiting
    [R] In Review
    [x] Approved
    [S] Skipped
    Part 6 · Engine & Safety

    Engine, Guards (Fences), Sensors, Agents & Tools

    Every deterministic tool, hook, sensor, reviewer, and MCP integration under the hood.

    The Conductor ↔ Deterministic Engine Loop

    The Conductor (SKILL.md) NEVER decides routing. It calls aidlc-orchestrate.ts (6 subcommands: next, continue, report, park, team-board, wait).
    1. engine next
    Conductor asks the Engine what happens next.
    2. Typed Directive
    Engine emits: run-stage, ask, invoke-swarm, print, or done.
    3. Execute Station
    Conductor runs the stage/agent, asks human if needed, fires sensors.
    4. engine report
    Reports structured result back to Engine; loop repeats.

    core/ — Neutral methodology & engine
    harness/<name>/ — Thin per-tool manifests
    plugins/<name>/ — Additive optional plugins
    bun scripts/package.ts
    Replaces {{HARNESS_DIR}}, projects files, and checks byte-for-byte determinism (--check).
    + build-binaries.ts → native aidlc
    Native Channel (Recommended): Standalone aidlc binary + runtimes. No Bun/Node/Git needed!
    Copy Channel: Manual runtime/<harness>/ folder copy (requires Bun).
